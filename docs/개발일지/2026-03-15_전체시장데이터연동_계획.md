## 해결하고자 한 문제

Pro 대시보드가 14개 하드코딩 종목만 보여주는 상태. 실제 Pro 서비스로 가치가 있으려면 **한국 전체 시장(KOSPI + KOSDAQ ~2,400개)과 미국 전체 시장(~5,500개)** 종목을 조회·스크리닝할 수 있어야 한다.

**핵심 제약 조건**:
- 오직 무료 API만 사용
- GitHub Actions 무료 티어: 월 2,000분 (비공개 repo 기준)
- Supabase 무료 티어: DB 500 MB

---

## 해결된 것 (설계 완료)

### korea-stock-mcp 재검토

`jjlabsio/korea-stock-mcp`는 TypeScript/STDIO MCP 서버라 Python FastAPI에서 직접 호출 불가. 하지만 이 서버가 내부에서 사용하는 동일한 KRX + DART API를 Python에서 직접 호출할 수 있다:

- KRX 데이터 → **PyKRX** (동일 KRX API 래핑, 벌크 엔드포인트 제공)
- DART 종목 코드 → **OpenDartReader** (Python DART 클라이언트)

### 데이터 소스 확정

| 시장 | 종목 유니버스 | 가격/PER/PBR | 심층 재무 |
|------|------------|------------|---------|
| KR | OpenDartReader (`dart.corp_codes`) | PyKRX bulk (2-4 API 호출로 2,400개 전체) | dartlab (시총 Top 50) |
| US | SEC EDGAR (`company_tickers.json`, 무료, 키 불필요) | yfinance.download 배치 (1,000개씩 6배치) | yfinance .info (S&P 500 ~500개) |

### 2-티어 아키텍처

- **Tier 1 (전체)**: 가격 + PER + PBR + 시총 — KR 2,400 + US 5,500 전부
- **Tier 2 (심층)**: ROE + 마진 + 성장률 + AI Score — KR Top 50 + US S&P 500

### 예산 검증

- GitHub Actions: ~36분/일 × 30일 = 1,080분 → **2,000분 한도의 54%**
- Supabase 신규 테이블: ticker_universe + market_snapshot = ~3.6 MB → **500 MB의 0.7%**

### 신규 Supabase 테이블 설계

- `ticker_universe`: 종목 메타 (8,000행, 주 1회 갱신)
- `market_snapshot`: 일별 OHLCV + PER/PBR (최근 3일 유지, 24,000행)

### 신규 백엔드 API

- `GET /api/market/full` — 전체 종목 페이지네이션 (market/sector/sort 필터)
- `GET /api/market/full/search?q=삼성` — 종목명/심볼 검색

### 신규 프론트엔드 컴포넌트

- `ProMarketList.tsx` — 기존 ProAllTickers 대체, 8,400개 페이지네이션 테이블
- `ProMarketFilter.tsx` — 시장/섹터/PER/시총 필터 패널
