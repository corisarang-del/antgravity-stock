## 해결하고자 한 문제

Phase 9 구현 완료 후, 실시간으로 검색이 필요한 부분은 캐시 딜레이를 최소화하고
꼭 실시간이 필요하지 않은 부분은 리프레시 주기를 최대한 늘려야 한다는 요구.

분석 대상: 백엔드 TtlCache TTL 8개 + 프론트엔드 staleTime 8개

### 핵심 발견: 백엔드-프론트엔드 TTL 불일치

**재무지표**: BE 30분 vs FE 8시간
- 백엔드가 30분마다 캐시를 버리지만, 실제 데이터는 24시간에 1번만 갱신
- 불필요한 Supabase/외부API 재호출 발생 가능성 있음
- 프론트엔드 8시간이 오히려 데이터 갱신 주기에 맞는 설정

**섹터 히트맵**: BE 5분 vs FE 4시간
- 백엔드 5분 캐시는 의미 없음 — 데이터는 GH Actions로 24시간에 1번 갱신
- 5분마다 Supabase에서 동일한 데이터를 재조회하는 낭비

**전체종목 목록**: BE 5분 / FE 5분
- 마찬가지로 24시간 갱신 데이터를 5분마다 재조회

### 검색 API 캐시 누락 발견

`GET /api/market/full/search?q=...` — 현재 캐시 없음
- 동일 검색어로 연속 요청 시 매번 Supabase ILIKE 쿼리 실행
- 예: 자동완성 UI 구현 시 키입력마다 요청 → burst 상황 위험
